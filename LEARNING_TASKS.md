# Learning tasks for my shell setup

Этот файл — практический план, чтобы освоить новый shell setup не по теории, а руками.

Формат простой:
- что изучаем
- какими командами пользоваться
- что сделать руками
- что должно получиться в итоге

---

## 0. База: понять prompt

Сейчас prompt показывает:

- короткую директорию
- git branch
- git status

### Git status в prompt
- `●N` — staged файлов: `N`
- `✎N` — changed, но не staged: `N`
- `+N` — new/untracked файлов: `N`
- `⇡N` — локальная ветка впереди origin на `N` коммитов
- `⇣N` — локальная ветка позади origin на `N` коммитов

### Задача
1. Зайди в любой git-репозиторий.
2. Создай новый файл.
3. Измени существующий файл.
4. Сделай `git add` только одного файла.
5. Посмотри, как меняется prompt.

### Цель
Начать считывать состояние репозитория, вообще не вводя `git status`.

## 1. Навигация по директориям: zoxide + cdf

### Инструменты
- `z` / `cd` (через zoxide)
- `cdf`
- `cdfa`
- `eza`

### Как пользоваться
- `cd project-name` / `z project-name` — прыжок в часто используемую директорию
- `cdf` — быстрый и неглубокий выбор директории через `fzf` (до 3 уровней)
- `cdfa` — глубокий поиск по всему дереву, если это реально нужно
- `ls`, `ll`, `la`, `lt` — просмотр файлов

### Задача
1. Несколько раз походи по 5–10 проектам через обычный `cd`.
2. Потом попробуй прыгать по частям имени:
   ```bash
   z secretary
   z dotfiles
   ```
3. Запусти:
   ```bash
   cdf
   ```
   и выбери нужную папку через fuzzy search.
4. Если нужен полный глубокий поиск — попробуй:
   ```bash
   cdfa
   ```
5. Просмотри структуру:
   ```bash
   ll
   lt
   ```

### Цель
Привыкнуть не печатать полные пути руками.

## 2. Поиск файлов и кода: fd + rg + fzf + bat

### Инструменты
- `fd`
- `rg`
- `vf`
- `rgv`
- `bat`

### Как пользоваться
- `fd query` — искать файлы по имени
- `rg query` — искать по содержимому
- `vf` — выбрать файл через `fzf` и открыть в редакторе
- `rgv "query"` — найти строку и открыть сразу в редакторе на нужной строке

### Задача
1. Найди файлы по имени:
   ```bash
   fd zsh
   fd toml
   fd -e go
   ```
2. Найди текст по проекту:
   ```bash
   rg "TODO"
   rg "main"
   rg "starship"
   ```
3. Открой файл через fuzzy picker:
   ```bash
   vf
   ```
4. Открой результат поиска сразу в редакторе:
   ```bash
   rgv "TODO"
   rgv "git_status"
   ```

### Цель
Перестать искать файлы руками через `find` и переходы по папкам.

## 4. Git everyday workflow

### Инструменты
- `git st`
- `git lg`
- `git last`
- `gd`, `gds`, `gsh`
- `gbr`
- `glogf`
- `gfixup`
- `gcf`
- `lg`

### Как пользоваться
- `git st` — короткий статус
- `git lg` — красивый граф коммитов
- `git last` — последний коммит со статистикой
- `gd` — diff
- `gds` — staged diff
- `gsh` — show commit
- `gbr` — выбрать ветку через `fzf`
- `glogf` — выбрать commit через `fzf` и посмотреть его
- `gfixup` — выбрать commit и сделать `fixup!`
- `gcf` — выбрать изменённый файл и открыть в редакторе
- `lg` — lazygit

### Задача A: базовый git loop
1. Открой репозиторий.
2. Сделай несколько изменений в файлах.
3. Посмотри статус:
   ```bash
   git st
   ```
4. Посмотри diff:
   ```bash
   gd
   ```
5. Добавь часть файлов в index:
   ```bash
   git add <file>
   ```
6. Посмотри staged diff:
   ```bash
   gds
   ```

### Задача B: навигация по истории
1. Выполни:
   ```bash
   git lg
   glogf
   ```
2. Найди интересный коммит и просмотри его.
3. Открой последний коммит:
   ```bash
   git last
   ```

### Задача C: branch workflow
1. Создай новую ветку:
   ```bash
   git sw -c test-shell-flow
   ```
2. Переключись между ветками через:
   ```bash
   gbr
   ```

### Задача D: fixup workflow
1. Сделай коммит.
2. Потом ещё небольшую правку к нему.
3. Выполни:
   ```bash
   gfixup
   ```
4. Потом посмотри историю:
   ```bash
   git lg
   ```
5. Осознай, как это дружит с `git rebase -i --autosquash`.

### Задача E: открыть изменённый файл
1. Измени несколько файлов.
2. Выполни:
   ```bash
   gcf
   ```
3. Выбери нужный файл и проверь, что он открылся в редакторе.

### Цель
Сделать git быстрее и визуальнее, без постоянной ручной печати длинных команд.

## 6. Локальные env и версии тулов: direnv + mise

### Инструменты
- `direnv`
- `mise`

### Как пользоваться
- `direnv` автоматически грузит env при входе в директорию
- `mise` управляет версиями языков/инструментов

### Задача A: direnv
1. Создай тестовую директорию:
   ```bash
   mkcd ~/tmp/direnv-demo
   ```
2. Создай `.envrc`:
   ```bash
   echo 'export DEMO_ENV=hello' > .envrc
   ```
3. Разреши:
   ```bash
   direnv allow
   ```
4. Проверь:
   ```bash
   echo $DEMO_ENV
   ```
5. Выйди из папки и снова проверь — переменная должна исчезнуть.

### Задача B: mise
1. Посмотри установленные инструменты:
   ```bash
   mise ls
   ```
2. Посмотри help:
   ```bash
   mise --help
   ```
3. На отдельном тестовом проекте попробуй локально задать версию runtime.

### Цель
Понять, как делать project-local окружение без глобальной каши.

## Шпаргалка: чем теперь пользоваться вместо старых привычек

### Навигация
Вместо:
```bash
cd /very/long/path/to/project
```
используй:
```bash
z project
cdf
# если нужен глубокий рекурсивный поиск
cdfa
```

### Поиск файлов
Вместо:
```bash
find . -name '*something*'
```
используй:
```bash
fd something
vf
```

### Поиск по коду
Вместо:
```bash
grep -R "query" .
```
используй:
```bash
rg "query"
rgv "query"
```

### Git status / log / diff
Вместо:
```bash
git status
git log --oneline --graph --decorate --all
git diff
```
используй:
```bash
git st
git lg
gd
```

### Изменённые файлы
Вместо ручного просмотра списка:
```bash
git status
nvim file
```
используй:
```bash
gcf
```

### Вспомнить синтаксис команды
Вместо:
```bash
man tar
```
используй:
```bash
tl tar
```
